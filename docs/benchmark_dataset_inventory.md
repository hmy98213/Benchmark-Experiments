# Benchmark Dataset Inventory

This document separates datasets already wired into this repository from benchmark workloads that are only proposed follow-ups.

## Implemented Now

| Workload | Data source | Current measurement path | Notes |
| --- | --- | --- | --- |
| `random` | Generated by vLLM | `vllm bench serve --dataset-name random` | Synthetic prompt tokens; no external dataset file. |
| `prefix_repetition` | Generated by vLLM | `vllm bench serve --dataset-name prefix_repetition` | Synthetic repeated-prefix prompts; useful for stressing reuse-heavy decoding. |
| Spec-Bench | `https://raw.githubusercontent.com/hemingkx/Spec-Bench/refs/heads/main/data/spec_bench/question.jsonl` | `vllm bench serve --dataset-name spec_bench --dataset-path ...` | Implemented through `scripts/download_bench_data.sh` and H100 Spec-Bench cases. |

## Proposed But Not Implemented

| Workload | Public data availability | What would be needed |
| --- | --- | --- |
| SWE-Bench | Public static benchmark datasets are on Hugging Face, e.g. `SWE-bench/SWE-bench` and `SWE-bench/SWE-bench_Verified`. | This is not a direct `vllm bench serve` dataset. To reproduce the paper-style workload, run an agent such as OpenHands against vLLM and record/replay OpenAI-compatible requests, or convert saved agent trajectories into prompt/response traces. |
| SWE-Bench Verified trace | The Verified task set is public; the exact request traces used by the SuffixDecoding paper are not bundled in vLLM or this repo. | Need a trace collector around an agent run, or an open trajectory dataset that has complete chat/action/tool-observation turns. Then benchmark by replaying those requests into vLLM. |
| AgenticSQL | The paper describes it as a proprietary multi-agent SQL workflow. | Cannot download the original dataset. A fair open substitute would be a multi-stage Text-to-SQL pipeline over Spider/BIRD-like data, with stages such as classify, extract, enrich, SQL candidates, and combine, then replay those stage prompts. |

## Important Distinction

`vllm bench serve` measures serving performance from prompt requests. It does not run a full agent loop and does not score task correctness.

For agentic workloads such as SWE-Bench and AgenticSQL, there are two possible measurement styles:

1. Live agent run: run the actual agent against a vLLM OpenAI-compatible endpoint and measure end-to-end wall time, token throughput, and speculative acceptance stats.
2. Trace replay: collect or download prompt/response traces, then replay each LLM call through vLLM to isolate decoding performance.

The current repository implements the first layer: starting vLLM, running `vllm bench serve`, and collecting per-case metrics. It does not yet implement agent trace collection or replay.
